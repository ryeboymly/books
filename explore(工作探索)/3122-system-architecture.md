```

│                    124个知识库, 两种类型                              │

│                                                                     │
│  ┌─ Document类型 ───────────────────────────────────────────────┐  │
│  │  结构: 一个文档 = 多个chunk (按段落/页切分)                   │  │
│  │  格式: docx/pdf/pptx/xlsx/md/png                              │  │
│  │  检索: 语义/关键词/混合, 命中后read_document读上下文          │  │
│  │  示例: weknora://kb/21d3c7cf-8ac6-4eb3-8979-618d395c2331 MES (12056篇文档)                             │  │

│  └───────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  检索流程:                                                          │
│  用户问题                                                           │
│    → 锁定相关知识库 (非全量搜索)                                    │
│    → 第一轮: 语义检索 (hybrid模式)                                  │
│    → 评估: 命中→读取片段; 未命中→第二轮                             │
│    → 第二轮: 关键词检索 (精确匹配标识符/错误码)                     │
│    → 仍未命中→如实告知                                              │
│    → 上限: 2轮, 每轮≤3片段, 同ID不重复读                            │
└─────────────────────────────────────────────────────────────────────┘
```

## 九、可优化 vs 不可优化（按步骤拆解）

| 步骤 | 环节 | 可控性 | 说明 |
|------|------|--------|------|
| ① | 平台注入上下文 | ❌ 不可控 | 平台自动注入 system prompt + runtime_context + summary |
| ① | 冷启动恢复 | ✅ 可控 | R3规则卡已优化为一条shell_exec恢复 |
| ② | LLM理解与分类 | ⚠️ 半可控 | 分类逻辑由system prompt决定，但我可以通过mly规则影响行为模式 |
| ③ | 检索流程 | ⚠️ 半可控 | 检索策略由system prompt锁定（2轮上限），但知识库选择和评估闸门由我执行 |
| ④ | 技能/工具调用 | ✅ 可控 | 工具选择、并行调用、脚本执行策略由我决定 |
| ⑤ | 生成回答 | ⚠️ 半可控 | 输出规则由system prompt约束，但内容组织和效率由我决定 |
| ⑥ | 平台后处理 | ❌ 不可控 | ref标签替换、sandbox渲染由平台自动完成 |
| ⑦ | 会话管理 | ❌ 不可控 | summary压缩完全由平台控制 |
