沙箱安全自查 39 项

一份可以拿去核对任何容器、虚拟机或 AI agent 运行环境的通用清单。每一项只回答一个问题：这个环境在这件事上是怎么配的。

通用版 · 2026-11-28 · 只讲查什么、为什么查，不含任何具体环境的观测值

怎么用：逐项对照，结果只填三种——通过、不通过、看不到。看不到的项不要猜，标出来交给有权限的人回答。全部只读：查配置不是测漏洞，不要为了填表去试连、扫描或绕过。

一、身份和权限

#查什么为什么查
1运行身份（uid 是不是 0）以管理员身份运行，意味着一旦被骗执行一段坏指令，那段指令也是管理员权限。身份该降没降，是这一组的第一条。
2capabilities（保留了多少能力位）能力位决定它能改水电、拆墙还是只能开门看表。出现 SYS_ADMIN、NET_RAW 这类，等于留了后门级权限。
3user namespace 是否映射把管理员身份在门外换成临时工号，容器里的 root 就不再是宿主 root。
4AppArmor / SELinux 是否启用给程序发一本行为守则，越界动作直接拦下，不依赖程序自觉。
5是否共用宿主网络 / 进程 / IPC和邻居共用一套水电表，隔离就只剩个名字。
6设备暴露（/dev 给了多少）插座口开得越多，能接上的东西越多，GPU、USB 直通都属于这一类。
7宿主内核与运行时补丁节奏内核是共享的，补丁慢一天，所有租户一起承担。
8是否默认禁止特权容器超级管理员模式应该是例外，不是默认可选项。
9seccomp 过滤与 no_new_privs门禁白名单加"不许再给自己升职"。这两项开着，能挡掉一大批越权动作。

二、门和墙

#查什么为什么查
10控制面 socket 是否可见docker、containerd 这类 socket 是整栋楼的总闸遥控器，递进来隔离基本作废。
11宿主目录是否 bind 挂载把别人家仓库直接接到自己屋里，读写都不再受边界约束。
12hostPath 类挂载是否白名单K8s 场景下的同一个问题，白名单化才有边界。
13/tmp 是否单独挂载并禁执行公共白板区谁都能写，不设 nosuid、nodev、noexec，放进去的东西就能直接跑起来。
14根文件系统是否只读墙和家具能改，坏东西就能把自己藏进系统目录。配合每轮重置能削掉大半危害。
15卷内密钥文件权限抽屉里该放公开证书，不该放私钥；放了私钥，权限至少 0600。
16共享卷是否多实例共用几个房间共用一个抽屉，等于一条不受控的信道。
17镜像层是否烤进构建期 secret装修时把钥匙砌进墙里，后面怎么加固墙都还在。

三、干多少活

#查什么为什么查
18pids.max 是否设置同时最多几个工人。不设上限，一段进程爆炸就能把宿主拖死。
19内存与 CPU 限额水电上限，防止一个实例把整层楼用完。
20磁盘配额写满磁盘是最朴素也最有效的破坏方式。
21文件描述符上限同时最多开几个文件，过低会自己崩，过高会拖垮别人。
22单轮执行超时一次干活最多多久。对短轮次的 agent，这条决定它会不会卡死在一个循环里。

四、钥匙和数据

#查什么为什么查
23云元数据服务是否封禁门口的身份卡自助机，能访问就能拿到临时凭据。检查方式是问平台，不是在容器里试连。
24环境变量是否长期挂 token钥匙挂在门口挂钩上，谁经过都能拿，子进程还能继承。
25token 的 scope 与轮换一把钥匙能开几道门、多久换一次、丢了能不能吊销。
26凭据注入方式走聊天附件，就等于每次递钥匙都留一份复印件在记录里。
27跨租户数据隔离能不能看到别家公司的东西，这条决定一次失守的影响半径。
28出网白名单只准去指定的几道门，比默认全开要安全得多。
29DNS 是否受控电话簿能查任意号码，想去哪都能问到路，数据外带就少了一道阻碍。
30出网策略由谁审批默认拒绝还是默认放行，粒度到域名还是到 IP。

五、AI agent 特有的坑

#查什么为什么查
31间接提示注入读到的网页、知识库、文档里的字，会不会被当成指令执行。这是 AI 独有的坑，不靠漏洞就能生效。
32工具调用白名单只能用工具箱里批准的扳手，越界要拒绝，而不是"尽力尝试"。
33多 agent 代理链审计通过中间人办的事记在谁账上。记错了，出了事分不清是谁做的。
34跨轮持久状态沙箱重置了，写进仓库、信箱、记忆的东西不会重置。状态到底存在哪，要说得清。
35输出面（公开仓、外部聊天）能不能把内部数据写到公开可见的地方。公开仓等于对外公告栏。
36自我修改能不能改自己的 prompt、规则、工具配置。能改，就等于能给自己扩权。

六、出事能不能查

#查什么为什么查
37操作日志与保留期里面干的事有没有录像、留多久、能不能被改。
38高权限操作单独审计管理员动作要单独记账，并且能分清是哪个 agent 做的。
39隔离、吊销与回滚出事能不能一键关停、收回钥匙、撤销写入。这条决定损失是一次性还是持续性的。

优先级

先看 1、2、10、11：身份、权限裁剪、控制面 socket、宿主挂载。这四项任意一条不过，后面的加固效果都会被打折。

再看 23、24、31、35、36：元数据服务、环境变量凭据、间接注入、公开仓外带、自我修改。这五项不需要逃逸就能造成实际损失，比容器逃逸现实得多。

一条经验：拿不到答案的项，比"不通过"更值得盯。看不到通常意味着权限不在你手上，出事时也轮不到你处置。

本清单只用于自查与加固，不构成任何绕过或测试授权。对非自有系统做任何探测都应先取得书面授权。
